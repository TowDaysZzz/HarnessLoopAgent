## Purpose

为每一种已识别意图提供单一、可替换和可测试的执行边界，让确定性业务操作、带证据的笔记问答、普通聊天、复杂任务和澄清结果共享同一条 Run 与 SSE 生命周期。

## ADDED Requirements

### Requirement: Executor 按意图选择执行路径

系统 SHALL 根据已确认的业务意图与复杂度组合选择唯一执行器；执行器结果 MUST 回写到当前 Run，并通过既有 SSE 事件协议输出状态、文本、工具结果和终态。确定性操作与流式模型操作可以使用不同的 handler 接口，但 MUST 汇聚到同一 Run 生命周期。

#### Scenario: 执行笔记查询

- **WHEN** 路由意图为 `note.query`
- **THEN** 系统调用笔记语义检索并使用现有证据门禁、引用白名单和不足拒答策略生成答案

#### Scenario: 执行普通聊天

- **WHEN** 业务意图为 `chat` 且复杂度为 `simple`
- **THEN** 系统将会话上下文交给普通 Eino 模型执行器并流式返回答案

#### Scenario: 直接保存明确给出的笔记内容

- **WHEN** 业务意图为 `note.create`，且当前消息明确给出可保存的笔记内容
- **THEN** 系统调用确定性的笔记写入端口，返回保存状态或待同步状态，且不得使用模型生成“已保存”事实

#### Scenario: 从聊天历史生成笔记候选

- **WHEN** 业务意图为 `note.create`，且用户要求从当前会话历史总结或提取笔记
- **THEN** 系统基于当前用户有权访问的会话上下文生成待确认的标题和正文候选，并持久化为当前会话的待确认草稿；确认前不得写入正式笔记或 RAG

#### Scenario: 确认聊天历史笔记候选

- **WHEN** 用户在同一会话中明确确认最新的待确认笔记候选
- **THEN** 系统调用确定性的笔记写入端口并将草稿标记为已确认，返回保存或待同步状态

#### Scenario: 取消或替换笔记候选

- **WHEN** 用户拒绝候选或要求修改候选内容
- **THEN** 系统不得写入正式笔记；拒绝时取消草稿，修改时生成新的待确认版本并再次等待确认

#### Scenario: 聊天请求删除笔记

- **WHEN** 业务意图为 `note.delete`
- **THEN** 系统明确告知聊天不支持删除，并引导用户使用笔记页面或删除 API，不得调用删除工具或删除接口

#### Scenario: 执行复杂任务

- **WHEN** 复杂度为 `complex`
- **THEN** 系统调用复杂任务执行器；当前实现至少可复用单 Agent Workflow，并保留替换为多 Agent 编排的接口

#### Scenario: 执行歧义澄清

- **WHEN** 路由意图为 `intent.unclear` 或执行器发现缺少必要参数
- **THEN** 系统返回可操作的澄清文本并将当前 Run 正常置为 `completed`，不调用不相关工具；用户下一条消息作为同一会话中的新 Run 正常继续对话

### Requirement: 待确认笔记草稿受会话和用户隔离

系统 SHALL 将从聊天历史总结出的候选笔记作为待确认草稿保存，并绑定用户、租户和会话。草稿 MUST 有明确状态和有效期，且只能由同一用户在同一会话中确认、修改或取消。

#### Scenario: 跨会话确认候选

- **WHEN** 用户在另一个会话中发送通用“确认保存”
- **THEN** 系统不得确认原会话草稿，并提示回到原会话或重新生成候选

#### Scenario: 草稿过期

- **WHEN** 用户确认的草稿已过有效期或已被新版本替换
- **THEN** 系统不得保存该草稿，并要求重新生成或确认最新候选

### Requirement: 执行器错误和权限边界一致

所有执行器 SHALL 继承当前用户、租户、会话和知识库权限；工具、RAG 或模型失败 MUST 通过统一 Run 错误事件返回，并不得泄露 Token、密码、Cookie 或跨用户数据。

#### Scenario: RAG 证据不足

- **WHEN** `note.query` 的检索未通过证据门禁或引用校验
- **THEN** 系统返回固定的证据不足答复，不使用模型常识补全

#### Scenario: 执行器超时

- **WHEN** 任一执行器超过 Run 或调用预算
- **THEN** 系统终止该执行器，记录超时指标并发送终态事件
