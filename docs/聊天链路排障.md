# 聊天链路排障

## 从 Run ID 开始

前端输入框上方会显示“运行中 Run”或“最近一次 Run”。这个 ID 与 `agent_runs.id` 相同，并贯穿以下位置：

- `agent_run_events.run_id`：路由、执行器、文本增量、工具结果和终态事件；
- Agent runtime 日志中的 `run_id`：模型调用、工具调用、校验和耗时；
- Agent 请求 RAG 时的 `X-Request-ID`：用于关联 RAG 服务日志。

前端失败提示也会保留 Run ID。定位问题时不要只记录页面文案，应同时记录 Run ID 和发生时间。

## 检查服务状态

```bash
curl -i http://127.0.0.1:8080/healthz
curl -i http://127.0.0.1:8080/readyz
curl -i http://127.0.0.1:5173/
```

`/healthz` 检查进程是否存活，`/readyz` 检查服务是否已准备好处理请求。

## 查询 Run 和事件

以下请求需要有效的 HttpOnly Session Cookie。使用 curl 调用登录接口时通过 `-c cookie.txt` 保存临时 Cookie，再在后续请求中通过 `-b cookie.txt` 使用；排障结束后删除该临时文件。

```bash
RUN_ID='<页面显示的 Run ID>'

curl -sS -b cookie.txt "http://127.0.0.1:8080/v1/runs/${RUN_ID}"
curl -N -b cookie.txt "http://127.0.0.1:8080/v1/runs/${RUN_ID}/events"
```

事件应按以下主干出现：

```text
run.queued -> run.started -> route.decided -> executor.started
           -> text.delta/tool.completed/note.draft.candidate
           -> executor.completed -> run.completed
```

异常终态可能是 `run.failed`、`run.timed_out`、`run.cancelled` 或 `run.interrupted`。如果只有 `executor.failed` 且错误码是 `stream_closed`，说明底层 Runner 违反了“必须发送终态事件”的流协议。

## 查询 Agent 日志

```bash
RUN_ID='<页面显示的 Run ID>'
docker logs --since 30m harnessloop-agent-chat-it 2>&1 | rg "${RUN_ID}"
```

重点观察 `run.start/run.end`、`model.start/model.end`、`tool.start/tool.end`、`evidence.evaluated` 和 `answer.validated`。同一个 Run ID 也会作为 RAG 请求的 `X-Request-ID`，可在 RAG 服务日志中继续检索。

## 当前 Trace 边界

当前链路已经具备统一 Run ID、持久化事件、模型与工具耗时日志以及 RAG 请求关联，可以处理大多数单次对话故障。当前还没有 OpenTelemetry `trace_id/span_id`、集中式 Trace 查询页面和 Prometheus exporter；跨进程时依赖 Run ID 查询日志，而不是自动生成完整调用瀑布图。
