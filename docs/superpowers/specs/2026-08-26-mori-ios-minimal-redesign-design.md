# Mori 极简 iOS 风格前端改版设计

## 目标

在不改变现有笔记、知识库和聊天业务能力的前提下，将 Mori 前端统一为柔和、极简、偏 iOS 的视觉与交互风格，同时修复已经确认的横向拖拽、移动端视口、无效交互和聊天异常状态问题。

成功标准：

- 页面以雪色为主背景，默认文字为黑色，绿色承担主操作与选中状态，蓝色承担链接与文字强调。
- 桌面端保持高效侧边栏结构，移动端使用带安全区的底部 Tab Bar。
- 320px、390px、834px 和 1280px 视口均不产生非预期的文档级横向滚动。
- 所有可见按钮都有真实行为或明确状态，不展示无响应的假入口。
- 键盘、屏幕阅读器和触控用户能够识别并操作主要导航与表单。

## 视觉系统

### 颜色语义

| 角色 | 色值 | 用途 |
|---|---|---|
| 主背景 | `#FFFAFA` | 页面底色、登录页与工作台背景 |
| 内容浮层 | `#FFFFFF` | 卡片、输入区、弹层 |
| 主高亮 | `#2E8B57` | 主按钮、当前导航、焦点状态、成功状态 |
| 默认文字 | `#1C1C1E` | 标题与正文 |
| 次级文字 | `#636366` | 描述、时间、元数据 |
| 弱化文字 | `#8E8E93` | 占位符、禁用提示 |
| 链接强调 | `#027AFE` | 文本链接、辅助跳转、可点击文字 |
| 分隔线 | `rgba(60, 60, 67, 0.12)` | 列表、导航、输入区边界 |

绿色不得大面积铺满普通内容区域。蓝色不得用于主提交按钮或当前导航，以维持绿色主操作、蓝色辅助链接的明确分工。

### 字体与层级

- 字体栈使用 `-apple-system, BlinkMacSystemFont, "PingFang SC", system-ui, sans-serif`。
- 默认正文使用正常字重与 `#1C1C1E`，不再依赖外部 Google Fonts。
- 大标题通过字号、字重和留白建立层级，不使用装饰性衬线字体。
- 链接和行内强调使用 `#027AFE`，必要时增加中等字重，不通过下划线堆叠视觉噪音。

### 形状与材质

- 卡片圆角统一为 16px，输入框与按钮圆角统一为 12px。
- 移动端触控目标最小高度和宽度为 44px。
- 使用细分隔线和极轻阴影；移除轨道圆环、彩色卡片顶线及多层重阴影。
- 顶栏、侧边栏和移动端 Tab Bar 可以使用低透明度白色与模糊材质，但必须保留足够对比度。

## 页面结构

### 登录页

- 宽屏保留品牌说明与登录表单双栏布局。
- 双栏只在可用宽度至少 880px 时启用；低于此宽度切换为单栏表单。
- 单栏状态展示精简品牌标识，不保留占空间的装饰背景。
- 表单输入和主按钮遵循 44px 最小触控尺寸。

### 桌面工作台

- 左侧保留窄侧边栏，包含品牌、笔记、对话及已实现的导航入口。
- 当前导航使用浅绿色底与绿色图标/文字；辅助文字跳转使用蓝色。
- 顶部保留搜索和一个轻量辅助操作。
- 主内容按“大标题—快速记录—最近笔记”的顺序形成单一视觉主线。
- 现有右侧洞察栏中的信息并入内容流，减少并列卡片和视觉竞争。

### 移动工作台

- 顶部只保留品牌或当前页面标题。
- 主导航移动到底部 Tab Bar；当前只展示已经可用的笔记与对话，收集箱实现后再加入。
- Tab Bar 使用 `env(safe-area-inset-bottom)` 适配 iPhone 底部安全区。
- 页面与聊天工作区使用动态视口高度，软键盘出现时输入框保持可达。

### 聊天页

- 桌面端保留会话列表与消息区双栏结构。
- 移动端会话历史以紧凑横向列表或独立入口呈现，消息与输入框保持主焦点。
- 消息区、会话历史和检索依据分别拥有明确滚动边界。
- 主发送按钮使用绿色；引用来源和可跳转文本使用蓝色。

## 交互行为

### 滚动与拖拽

- 根文档不得产生横向滚动，页面装饰不得撑大布局宽度。
- 视口容器使用 `100dvh`，并为不支持动态视口的浏览器保留合理回退。
- 聊天历史与消息列表使用受控滚动和 `overscroll-behavior: contain`，避免滚动传递到整页。
- 文本编辑区默认不允许通过拖拽改变布局尺寸；内容增长通过最大高度和内部滚动处理。

### 导航与按钮

- 移动端图标按钮保留可访问名称，不能通过隐藏文字同时移除 accessible name。
- 当前页面使用 `aria-current` 或等价的选中语义。
- 未实现的收集箱、置顶、标签管理、空间切换等入口暂时隐藏，不渲染成无响应按钮。
- `⌘K` 提示仅在搜索聚焦快捷键实际实现后显示。
- 删除笔记使用明确的菜单/确认状态，不以“三点”图标直接暗示删除。

### 动态内容

- 欢迎区日期由当前本地日期动态生成。
- 笔记创建、索引和删除状态使用统一的加载、成功和错误反馈。
- Toast 支持手动关闭，并提供合适的 live-region 语义。

## 聊天可靠性

- 发送消息后可以显示乐观消息，但创建 Run 失败时必须回滚临时助手消息，并明确标记或重新同步用户消息。
- 切换会话前清空或冻结旧消息；加载失败不能让旧消息显示在新会话标题下。
- `EventSource` 必须由组件生命周期管理；切换页面或卸载聊天组件时关闭连接。
- 流式请求完成、失败、取消或超时后统一恢复输入状态，并避免重复完成回调。

## 无障碍与动效

- 所有图标按钮提供 `aria-label`；选中导航提供可感知状态。
- 焦点环使用绿色半透明外圈，并确保键盘焦点始终可见。
- 正文、次级文字、绿色按钮和蓝色链接必须满足常规文本对比度要求。
- 动效控制在约 180–240ms，并遵循 `prefers-reduced-motion`。

## 验证方案

- 在 320×568、390×844、834×1112、1280×720 视口检查布局和横向溢出。
- 登录页在 820–879px 区间重点回归，确认 `scrollWidth` 不超过 `clientWidth`。
- 在移动 Safari 行为模型下检查地址栏收缩、软键盘、底部安全区和滚动边界。
- 使用键盘完成导航、搜索、创建笔记、切换会话和关闭提示。
- 检查所有可见按钮的 accessible name，并确认不存在无响应入口。
- 模拟聊天创建失败、流式中断、会话加载失败和组件卸载，验证状态回滚与连接清理。

## 非目标

- 本次不改变后端 API、知识库索引策略或聊天检索逻辑。
- 本次不新增收集箱、标签管理、空间管理等尚未实现的业务能力。
- 本次不引入完整第三方设计系统；视觉令牌和组件样式继续维护在现有前端工程内。
